# FRANCHISE OS — архитектура

## Принцип
Система разделяет:
- **плановые допущения**;
- **фактические показатели**;
- **зарезервированные деньги**;
- **свободный денежный поток владельца**.

## Модули
1. Обзор сети
2. Точки
3. Финансы / P&L
4. Сценарии
5. Персонал
6. Фонды
7. План открытий
8. Платежи
9. Настройки

## Текущая persistence-модель
MVP сохраняет изменения в localStorage, поэтому приложение уже интерактивно и автономно.

## Production persistence
Подготовлена схема Supabase:
- profiles
- locations
- employees
- monthly_pnl
- fund_transactions
- RLS для данных владельца

Следующий слой — Supabase Auth + repository/adaptor, чтобы UI и финансовые формулы не зависели от способа хранения данных.

## Основные финансовые определения
- Чистая прибыль приложения — модельный показатель на основе заданных пользователем ставок.
- Амортизационный и корпоративный фонды считаются зарезервированными расходами.
- Рассрочки франшизы показываются отдельно от операционного P&L зрелой точки.
- Маркетинговые обещания франшизы не используются как гарантированные показатели.
